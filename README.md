# Interactive 3D Map

An interactive 3D concept map of the planned **Blue Mountain Racing** motorsport destination in the Swartland, north of Cape Town, built with [Three.js](https://threejs.org). Part of Protium's partnership proposal to BMR. Visitors can orbit, zoom and pan around the circuit and precinct, click a building to see what it is, and search for a place to fly the camera to it.

The layout is illustrative. There's no published masterplan yet.

**Status:** All five phases of the build plan are built: the whole concept site, drawn from [src/data/locations.json](src/data/locations.json), on dressed farmland you can move around, with name labels, details for everything on the map, a searchable sidebar with precinct filters, and a race weekend / conference day switch. The frame rate on a real mid-range phone still has to be checked.

The procedural kit contains 82 models, plus six separately built crowd figures. The signature buildings use stepped roofs, terraces, skylights and exposed seating designed for the aerial camera. See the [asset review](tools/assets/aerial-review.md) for placement-weighted triangle counts and visual checks.

## Stack

| Piece | Choice |
| --- | --- |
| Rendering | Three.js |
| Language | TypeScript |
| Dev server / build | Vite |
| Camera | `MapControls` (from `three/addons`) |
| Labels | `CSS2DRenderer` (HTML labels pinned to 3D positions) |
| 3D models | glTF / `.glb`, generated by the kit in [tools/assets](tools/assets/README.md) |
| Map content | A JSON file describing every location |

## Running it

You need Node.js 22.18 or later and [pnpm](https://pnpm.io).

```bash
pnpm install
pnpm dev
```

`pnpm build` checks the layout, type-checks and writes a production build to `dist/`.

`pnpm check:layout` measures the circuit in the layout data and fails if it misses BMR's length, straight or width targets, or if a model the layout asks for doesn't exist.

`pnpm build:package` creates the shared library and runtime assets in `dist/`. Run it before package tests or packing. `pnpm test:browser` checks lifecycle, Strict Mode and tours in local Chrome.

`pnpm test` runs the tests in `tests/`. `pnpm lint` checks formatting and common mistakes with [Biome](https://biomejs.dev), and `pnpm format` fixes what it can.

Left-drag pans, right-drag rotates and scrolling zooms. On touch, one finger pans and two fingers zoom and rotate.

While it loads, the map shows a title screen with the circuit drawing itself. It then opens with a fly-in, skipped under reduced motion. Pointing at a location or its label highlights it. Clicking or tapping a building, gate or label opens its details and moves the camera to it. Roads, tracks, flat areas and water open their details where they are, without muting the rest of the site. Clicking empty ground, the close button or Escape closes the details.

The details list the closest gate and car park, which fly there when picked. Shuttles run round the ring road and traffic along the N7 in every view. On a race weekend ten race cars lap the circuit on a racing line, braking for the bends. A race weekend also draws the arrival routes: arrows along the roads from the N7 and the aerodrome to the car parks, and dots along the walks to the gates. They come from the `arrivals` list in the layout data. Two tour buttons ride the camera round the circuit behind a race car, showing its speed and turn, or from the N7 through Gate 2 to the main grandstands. Dragging, zooming or picking anything stops a tour, and under reduced motion the buttons are hidden. The selected location goes into the address as `?location=<id>`, so a copied link opens the map on it. Other parameters such as `?quality` are kept, and an id that doesn't exist is dropped.

The switch at the top of the map shows the site as a whole, on a race weekend or on a conference day. The locations in use stay in full colour and the rest are muted, with crowds of parked cars, the race grid or conference marquees appearing to match.

People on the banks, walks, fan villages and waterfront are simple cones and boxes from a distance. Within about 320 m of the camera they become a mix of six small figures, turned to face the track on the banks and the screen in the fan villages.

The sidebar lists every location by precinct. Typing in the search box filters the list, and Enter goes to the first match. Each precinct's switch fades it and its labels in or out. Picking a location in a hidden precinct brings that precinct back. "Reset view" closes the details and returns to the opening view. On a phone the sidebar is a sheet along the bottom: tap or drag its top strip to open it.

## Checking performance

The map draws less on phones: fewer trees and people, no glow, cloud shadows or blur over the picture, and the everyday movement at half the frame rate. It picks its tier from the device, and `?quality=low` or `?quality=high` in the address overrides that. If the frame rate drops below 28 fps while the view is moving, it lowers the resolution by itself.

`pnpm perf` starts the dev server, opens six fixed views on the high and low tiers in headless Chrome, and prints draw calls, triangles and a median frame time for each. `--compare tools/perf/baseline.json` shows the change from the saved baseline, and `--out` saves a new one. The counts are exact. The times only compare runs on the same machine.

Add `?stats` to the address to see the frame rate, draw calls and triangles once you've moved the map. To try it on a phone on the same Wi-Fi, run the dev server with `pnpm dev --host` and open the "Network" address it prints, with `?stats` added.
